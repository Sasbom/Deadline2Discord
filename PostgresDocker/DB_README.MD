# Small reference for Postgres use.

Some tips to get it all running smoothly.
1. The compose is really meant to run in a linux environment.
1. Use the official docker keyrings to get the latest docker compose etc!
1. WSL works too!
1. This compose also spins up a pgadmin container. You can leave that part out if you like.

The way this compose is set up, is to automatically make a new admin user and a database that belongs to them, if they don't exist. It runs a python script to generate SQL during DB initialization. 
If something messes up you can probably manually fix it with pgadmin, but I have had no problems so far. 

If the bot connects to the postgres instance, it won't dump everything in the main database unless you set it to use "postgres" as a database, it will create its own or connect to the one you specified, and then a schema within that also specifyable in the file generated by the secrets module. (Think of a schema as a "Group" of tables/functions/whatever else in a database).

From PGadmin, if you wanted to see all users, and you use the default "bot" name for schema, you'd query like this.
```SQL
SELECT * FROM bot.users;
```
